## IO 预算

### 可用引脚

按 ESP32-S3-WROOM-1U-N16R8（16 MB Flash、8 MB PSRAM、IPEX 天线座）计算。
模组引出 36 个 GPIO，其中 GPIO35 / 36 / 37 被 8 MB PSRAM 占用，**可用 33 个**：GPIO0 ~ 21、GPIO38 ~ 48。

### 放到 IO 扩展芯片上的慢信号（不占原生 GPIO）

用一颗 16 位 I²C 扩展芯片（XL9555 / TCA9555 一类），正好 16 路：

| 信号 | 路数 |
|---|---|
| 按键 KEY1 ~ KEY6 | 6 |
| Air780E：开机 PWRKEY、关机 RESET、状态 STATUS、DTR、电源使能 | 5 |
| 屏复位、触摸复位 | 2 |
| 前摄待机、后摄待机（切换前后摄） | 2 |
| 功放使能 | 1 |

不接或不占引脚的：摄像头复位（接上电复位电路，软件复位走 I²C）、触摸中断（改为轮询）、
Air780E 的 RI（不接）、充电状态（走充电芯片的 I²C 或指示灯）、SIM 卡检测（接 Air780E）、复位键（直接接 ESP32 的 EN）。

### 方案一：SPI 屏 —— 够用，含 TF 卡后全部用完

| 功能 | 原生 GPIO | 明细 |
|---|---|---|
| 摄像头（8 位并口，前后摄共用） | 12 | D0 ~ D7、PCLK、VSYNC、HREF、XCLK |
| 屏（四线 SPI） | 4 | CLK、MOSI、CS、DC |
| 背光调光 | 1 | PWM |
| 音频 | 4 | BCLK、WS、麦克风数据、功放数据（麦克风和功放共用时钟） |
| Air780E | 4 | TX、RX、RTS、CTS |
| I²C 总线 | 2 | 触摸、摄像头配置、扩展芯片、充电芯片共用 |
| USB | 2 | 下载、调试 |
| 扩展芯片中断 | 1 | 按键响应；休眠时按键唤醒 |
| 电池电压检测 | 1 | ADC |
| **小计（不含 TF 卡）** | **31** | 剩 2 个 |
| TF 卡（与屏共用 SPI 总线） | 2 | MISO、片选 |
| **合计（含 TF 卡）** | **33** | **剩 0 个** |

| GPIO | 用途 | 选这个脚的原因 / 注意 |
|---|---|---|
| 0 | 屏 DC | 启动配置脚：复位时必须为高。接的是屏的输入脚，不会被拉低。另留 BOOT 测试点 |
| 1 | 扩展芯片中断 | 属于休眠时仍可用的引脚，能用来唤醒 |
| 2 | 功放数据 | |
| 3 | 麦克风数据 | 启动配置脚，默认不起作用 |
| 4 ~ 8 | 摄像头 D0 ~ D4 | |
| 9 | 电池电压检测 | ADC1（Wi-Fi 工作时也能用的那组 ADC） |
| 10 / 11 / 12 | 屏 CS / MOSI / CLK | ESP32-S3 的专用高速 SPI 引脚 |
| 13 / 14 | TF 卡 MISO / 片选 | 与屏共用 MOSI、CLK |
| 15 / 16 | Air780E RTS / CTS | 串口 0 的专用流控引脚 |
| 17 / 18 / 21 | 摄像头 D5 ~ D7 | |
| 19 / 20 | USB D- / D+ | |
| 38 / 39 / 40 / 41 | 摄像头 PCLK / XCLK / VSYNC / HREF | |
| 42 / 46 | 音频 BCLK / WS | GPIO46 是启动配置脚，复位时要为低；接的都是输入脚，没问题 |
| 43 / 44 | Air780E 串口发 / 收 | 串口 0 的专用引脚，跑 921600 最稳 |
| 45 | 背光调光 | 启动配置脚，复位时必须为低；默认下拉，正好是"上电背光关" |
| 47 / 48 | I²C SDA / SCL | |

这个分配的代价：

- **没有任何备用引脚**。之后想加指示灯、4G 来数据唤醒主控、触摸中断等，都没有脚可用。
- **串口 0 给了 Air780E**，板上不再有独立的调试串口，调试和下载全靠 USB。
  ESP32-S3 上电时会从串口 0 打印启动信息，Air780E 会收到一小段乱码（它此时还没开机，无影响）。
- 四个启动配置脚（GPIO0、3、45、46）全部用上了，外接的器件在复位瞬间不能把它们拉到错误电平。
- 麦克风和功放共用时钟，两者必须用同一个采样率。

想留出余量，可以选下面的做法（每条省的引脚数写在后面）：

| 做法 | 省几个 | 代价 |
|---|---|---|
| 主板不带 TF 卡 | 2 | 没有本地存储扩展 |
| 用带 I²C 电压检测的充电芯片（BQ25895 一类）读电池电压 | 1 | 充电芯片选型受限 |
| 摄像头时钟用板上晶振，不由 ESP32 提供 | 1 | 多一颗晶振，待机功耗略增 |
| 屏的片选直接接地 | 1 | TF 卡不能再和屏共用总线 |
| Air780E 不接 RTS / CTS | 2 | 高波特率下可能丢数据，网速要降 |
| 改用 2 MB PSRAM 的模组（N16R2） | 多出 3 个 | 内存只有 2 MB，摄像头 + 界面 + 语音同时跑会很紧 |

### 方案二：实际选定的屏 LB28BOE47（480 × 640）—— 能接，但要砍功能，零余量

屏厂确认图给出的信息：2.83 寸 IPS，480 × 640，驱动芯片 **NV3049F**（不是 ST7701），接口"SPI + RGB"，22 脚 FPC。

| 脚 | 信号 | 脚 | 信号 | 脚 | 信号 |
|---|---|---|---|---|---|
| 1 | LEDA（背光 +） | 9 | G5 | 17 | HSYNC |
| 2 | LEDK（背光 −） | 10 | G4 | 18 | DE |
| 3 | SDA | 11 | G3 | 19 | VSYNC |
| 4 | SCL | 12 | G2 | 20 | RST |
| 5 | NC | 13 | G1 | 21 | GND |
| 6 | VCI（电源） | 14 | G0 | 22 | GND |
| 7 | G7 | 15 | CS | | |
| 8 | G6 | 16 | DOTCLK | | |

我对这份引脚表的解读（**标 ★ 的需要屏厂确认**）：

- ★ 数据线只有 8 根（G0 ~ G7），应该是 **8 位串行 RGB**：每个像素分 3 个时钟送出。
  乐鑫 LCD 指南写明 ESP32-S3 的 RGB 接口支持 16 位 RGB565 和 8 位 RGB888 两种，所以这种屏 ESP32-S3 能驱动。
- SDA、SCL、CS 是三线 SPI，只用来发初始化命令，可以挂在 IO 扩展芯片上，不占原生 GPIO。RST 也挂扩展芯片。
- 屏没有显存，主控要不停地送数据。帧缓冲 480 × 640 × 3 = 921 600 字节，放在 PSRAM 里，所以必须用 8 MB PSRAM 的模组。
- 每秒刷 30 帧需要约 32 MHz 的像素时钟（按每行每帧各加约 40 个消隐周期估算）。
  这个数据量 ESP32-S3 带得动，但同时还要跑摄像头，内存总线负担重，**有画面抖动的风险，要打样后才能确认**。
- 这条排线上没有触摸信号，触摸屏应该另有一条排线。
- 背光是 LEDA / LEDK 两根线，需要恒流驱动，电压电流待查。

引脚预算（TF 卡是必须的）：

这块屏不走 SPI 总线，TF 卡没法像方案一那样和屏共用总线，只能单独接（SD 一线模式：CLK、CMD、D0，3 个引脚）。

| | 引脚数 |
|---|---|
| 屏、背光、TF 卡以外的部分 | 26 |
| 屏：8 数据 + DOTCLK + HSYNC + VSYNC + DE | 12 |
| 背光调光 | 1 |
| TF 卡 | 3 |
| 合计 | 42 |
| 可用 | 33 |
| **缺口** | **9** |

把能省的全部省掉：

| 做法 | 省几个 | 代价 |
|---|---|---|
| ★ 屏只用 DE 模式（不接行场同步） | 2 | 要看 NV3049F 是否支持，需要屏厂确认 |
| 电池电压由带 I²C 检测的充电芯片读 | 1 | 充电芯片选型受限 |
| 摄像头时钟用板上晶振 | 1 | 多一颗晶振 |
| Air780E 不接 RTS / CTS | 2 | 高波特率下可能丢数据，网速要降 |
| 背光不由 ESP32 直接调光 | 1 | 扩展芯片要从 16 路换成 24 路 |
| 扩展芯片不接中断，改为轮询 | 1 | 按键不能把主控从休眠中唤醒 |
| **合计** | **8** | |

42 − 8 = 34，仍然比 33 多 1 个。

**结论：TF 卡必须有的前提下，ESP32-S3 接不下这块屏。** 只有不带 TF 卡时才勉强放得下（见上一版分析：
同时放弃流控和直接调光后刚好 33 个，零余量）。

之前按 ST7701（16 根数据线）估算的"缺 14 个、做不了"不适用于这块屏。

可选的出路：

1. **换成带显存的 SPI 屏**（比如 2.8 寸 240 × 320 的 ST7789）：回到方案一，TF 卡和屏共用总线，33 个引脚刚好用完；
   再用"充电芯片读电池电压"和"摄像头用板上晶振"两招，可以留出 2 个备用引脚。显示不占内存总线。
2. **保留这块 480 × 640 的屏，放弃 TF 卡**：勉强放得下，但没有流控、没有备用引脚，流畅度要打样验证。
3. **屏和 TF 卡都要**：换主控（例如带 MIPI 的 ESP32-P4，另配一颗 Wi-Fi 芯片），整个方案重排。

### 方案三：让 480 × 640 屏与 ESP32-S3 共存 —— 33 个引脚刚好放下，TF 卡保留

在方案二的基础上换三个做法，就能把缺口补上。每一条都查了官方文档，出处写在后面。

**1. Air780E 改用 USB 连接 ESP32-S3，不走串口（省 4 个）**

- ESP32-S3 的 USB 口（GPIO19 / 20）做主机，直接连 Air780E 的 USB。仍然是 AT 指令 + PPP 拨号，只是通道从串口换成 USB。
- 依据：乐鑫 `iot_usbh_modem` 组件的已支持模组列表里有 Air780E（固件 AirM2M_780EVT_V2010_LTE_AT），ESP32-S3 一栏为支持；
  合宙 AT 手册的 USB 模式里有"RNDIS + AT + PPP"。
- 好处：串口的收、发、两根流控共 4 个引脚全部省掉；USB 全速 12 Mbps，比串口 921600 快得多；AT 口和数据口可以同时用。
- 代价：Type-C 的数据线不能再直连 ESP32-S3。固件下载改走串口测试点（GPIO43 / 44 + GPIO0 + EN），量产用夹具，升级用 OTA。
  想保留"插电脑就能下载调试"，可以加一颗很小的 USB 切换芯片，在"接电脑"和"接 Air780E"之间切换。

**2. 屏的 8 根数据线只接高 5 位（省 3 个）**

- 8 位串行 RGB 是把红、绿、蓝各一个字节依次送出。只接每个字节的高 5 位，低 3 位在板上接地，颜色从 1677 万色降到 32768 色
  （和常见的 RGB565 屏观感接近，渐变处会有轻微色阶）。
- 依据：ESP-IDF RGB 屏驱动文档写明，数据线、行场同步、DE 等引脚"不用的设为 −1"。
- 如果后面省出引脚，可以接 6 位（26 万色，基本看不出差别）。

**3. 两个不占性能的小改动（各省 1 个）**

- 摄像头的主时钟用板上一颗晶振提供，不由 ESP32-S3 输出。
- 电池电压由带 I²C 检测的充电芯片读取。

**另外两点让引脚不浪费：**

- TF 卡用 SD 一线模式（3 个引脚）。依据：ESP-IDF 文档写明 ESP32-S3 的 SD 主机支持一线模式，且可以用任意 GPIO。
- 串口 0 的两个脚（GPIO43 / 44）平时当屏的同步信号用，下载时当串口用，不单独占引脚。

| 功能 | 原生 GPIO | 明细 |
|---|---|---|
| 摄像头（前后摄共用） | 11 | 8 数据 + PCLK、VSYNC、HREF |
| 屏 | 9 | 5 数据 + DOTCLK、DE、HSYNC、VSYNC |
| 背光调光 | 1 | |
| 音频 | 4 | BCLK、WS、麦克风数据、功放数据 |
| I²C 总线 | 2 | 触摸、摄像头配置、扩展芯片、充电芯片共用 |
| 触摸屏 | 0 | 数据走上面的 I²C；复位和中断挂扩展芯片 |
| USB（接 Air780E） | 2 | GPIO19 / 20 |
| TF 卡 | 3 | CLK、CMD、D0 |
| 扩展芯片中断 | 1 | 按键响应和休眠唤醒 |
| **合计** | **33** | **可用 33，剩 0** |

引脚分配草案（每个脚只用一次，33 个全部用上）：

| GPIO | 用途 | 说明 |
|---|---|---|
| 0 | 音频 BCLK | 启动配置脚，复位时要为高；只连板上麦克风和功放的输入脚，不会被拉低。另留 BOOT 测试点 |
| 1 / 2 | I²C SDA / SCL | |
| 3 | 功放数据 | 启动配置脚，默认不起作用；接的是功放的输入脚 |
| 4 ~ 11 | 摄像头 D0 ~ D7 | |
| 12 / 13 / 14 | 摄像头 PCLK / VSYNC / HREF | |
| 15 / 17 / 21 | TF 卡 CLK / CMD / D0 | 三根线都不放在启动配置脚上（TF 卡在板外，会热插拔） |
| 16 | 扩展芯片中断 | 休眠时仍可用的引脚，能唤醒 |

| 38 ~ 42 | 屏数据高 5 位（接屏的 G3 ~ G7） | |

| 45 | 背光调光 | 启动配置脚，复位时为低，正好是"上电背光关" |

| 47 / 48 | 屏 DOTCLK / DE | |

慢信号放在两颗 16 位 I²C 扩展芯片上（共 32 路，预计用 25 路左右）：6 个按键、屏的复位和三线 SPI、触摸的复位和中断、
前后摄切换、功放使能、Air780E 的开机 / 关机 / 状态 / 电源使能、TF 卡检测、USB 切换、各路电源使能。

性能评估：

- 刷新率：每帧约 100 万个像素时钟（含消隐）。像素时钟 26 MHz 左右时约 25 帧 / 秒。
  ESP-IDF 文档对 8 位数据宽度的建议是像素时钟低于 80 MHz，在范围内。
- 内存带宽：屏每秒从 PSRAM 读约 26 MB。乐鑫 FAQ 的实测数据是"八线 PSRAM 80 MHz 时像素时钟最高可设到 22 MHz"，
  按 16 位屏每个时钟 2 字节算约 44 MB / 秒（这个换算是我做的），需求在范围内，但余量不算大。
- 防画面漂移：按乐鑫 FAQ 的建议，开"代码放进 PSRAM 运行"和"Bounce Buffer"模式；Wi-Fi、写 Flash 时才不会漂移。
- 内存：帧缓冲 0.92 MB（双缓冲 1.84 MB），8 MB PSRAM 够用。也可以用驱动的"仅 Bounce Buffer"模式，
  帧缓冲按 RGB565 存（0.61 MB），送屏时再转换，省内存也省带宽。
- 摄像头取景：屏在不停刷新的同时还要把摄像头画面搬进帧缓冲，预计取景帧率只有 10 帧 / 秒上下。

RGB 屏和并口摄像头同时工作有官方依据：ESP32-S3 技术参考手册第 29 章（LCD_CAM）的特性列表写明
"支持同时连接外部 LCD 和外部摄像头"，并给出限制："两者同时连接时，接口上的总数据吞吐量要低于 GDMA 的总带宽 80 MB / 秒"。
按屏 20 ~ 30 MB / 秒、摄像头取景 6 ~ 12 MB / 秒估算，合计在这个限制之内（摄像头的数字是我的估算）。

仍然必须实测或由屏厂确认的两件事：

1. **NV3049F 的串行 RGB 时序和最低刷新率**，以及 8 根数据线里哪几根有效。公开渠道找不到它的数据手册，
   调研结果见 `nv3049f-research.md`。
2. **屏 + 摄像头 + USB 4G + 语音同时跑时的实际流畅度**（有没有画面漂移、取景帧率多少）。

关于"只接 5 根数据线"的注意点：不接的数据线在板上接地，电气上没有问题，屏一定能显示。
真正的风险是接错了位——面板是 RGB666，如果有效位是低 6 位而不是高 6 位，只接高 5 位会丢掉大部分亮度信息。
所以这一条要先在开发板上把 8 根线都接上试出来，或者等屏厂答复，再定 PCB 上接哪 5 根。

建议：画板之前先用现成的开发板（ESP32-S3 N16R8 开发板 + 这块屏 + OV2640 + Air780E 开发板）飞线验证这三件事，
大约一两周，能避免做出一块点不亮或卡顿的板子。

如果第一版 PCB 想保留"8 根数据线全接"的可能，可以用 0 Ω 电阻做二选一：
屏的低 3 位数据线默认接地，另留焊盘改接到 TF 卡用的那 3 个 GPIO（GPIO15 / 17 / 21）。两组焊盘只焊其中一组。
这样同一块板可以在"5 位数据线 + TF 卡"和"8 位数据线、不带 TF 卡"之间切换着测，不需要额外的 GPIO。

这个方案的代价汇总：

- 没有备用引脚（屏厂确认 DE 模式后可以空出 2 个）。
- 板上默认没有调试串口，Type-C 默认不能给 ESP32-S3 下载（加 USB 切换芯片可以解决）。
- 颜色 32768 色。
- 取景帧率偏低。
- Air780E 的连接方式从"串口"改为"USB"（已同意）。

### 考虑过的替代做法：把并口摄像头换成 SPI 摄像头

思路是摄像头改走 SPI（4 个引脚，比并口少 7 ~ 8 个），屏就可以接满 8 根数据线，4G 也可以继续用串口。
引脚上成立，但具体器件有问题：

- 200 万像素的 SPI 摄像头只有 Arducam Mini 2MP Plus 这类开发模块：板子 34 × 24 mm、带 M12 镜头座、
  SPI 最高 8 MHz、桥接芯片不单卖。尺寸放不进 64 × 34 mm 的主板和薄外壳，取景帧率也低。
- 真正能做进产品的 SPI 摄像头传感器分辨率都很低。乐鑫 FAQ 的说法是 ESP32-S3 可以接 SPI 接口的摄像头，
  但"分辨率比较小，240 × 320"。替代不了 200 万的后摄。
- 乐鑫摄像头组件（esp_cam_sensor / esp_video）的官方支持表进一步确认了这一点：
  - ESP32-S3 支持的摄像头接口有并口（DVP）、USB、SPI 三种，不支持 MIPI。
  - 表里走 SPI 的传感器只有两颗：BF3901（240 × 320，彩色，15 帧 / 秒）和 SP0A39（640 × 480，只有灰度；
    一线 SPI 下 4 帧 / 秒，15 帧 / 秒需要两线模式，而两线模式要用 ESP32-S3 没有的并行 IO 外设）。
  - SPI 摄像头占 3 个引脚（片选、时钟、数据）再加一路主时钟。
  - 官方注明："ESP32-S3 上 200 万像素只能用 OV2640 / OV3660 / OV5640 输出 JPEG 拍静态照片"，这三颗都是并口。
  - USB 摄像头在 ESP32-S3 的全速 USB 下最高 480 × 800、15 帧 / 秒，也到不了 200 万。
- 该做法的引脚表里没有算 TF 卡、前摄和扩展芯片中断；补上后同样是 33 个用满。

结论：后摄要 200 万就只能用并口，SPI 不采用；前摄改 SPI 反而要多占 3 个引脚、分辨率还更低，也不采用。保留它的两点建议——验证顺序（先单独点亮屏，再加摄像头和 4G，最后加音频做压力测试），
以及向屏厂确认最低刷新率、每像素时钟数、DOTCLK 范围和完整初始化代码。

关于刷新率上限有一处没有定论：乐鑫 FAQ 的实测是"八线 PSRAM 80 MHz 时像素时钟最高 22 MHz、120 MHz 时 30 MHz"，
但没有写明测试用的是 16 位屏还是 8 位屏。如果是 16 位屏（每个时钟 2 字节），换算到这块 8 位屏约可到 40 MHz 以上；
如果这个数直接适用于 8 位屏，就只有约 20 帧 / 秒。两种理解差一倍，只能靠点屏实测确定。

## 其它待定

- 北美版的运营商认证和 USB 拨号实测（见 `air780e-design-notes.md` 第 10 节）。
- 第一版板子给前后摄的并口线预留总线开关的位置，等前摄型号定了、确认待机时能否高阻后再决定贴不贴。
- 屏的复位线要有下拉，保证扩展芯片初始化之前屏一直处于复位状态（上电时 GPIO43 会打印启动信息，屏不能响应）。

- 前后摄像头共用一组并口数据线时，要确认两颗传感器待机时数据脚是否为高阻；不是的话要加总线开关。
  前摄的具体型号还没定。
- 屏：NV3049F 的数据手册或屏厂的初始化代码、RGB 模式（8 位串行？DE 还是行场同步）、背光电压电流、FPC 间距。
- 触摸屏：芯片型号和排线引脚定义。
- 6 个按键是否包含开关机键；开关机用"长按进出休眠"还是"硬件断电"。
- 外形：是否要与参考主板的外形、螺丝孔和座子位置一致。参考主板两面元件最高 1.75 ~ 1.9 mm，
  而 Air780E 高 2.3 mm、ESP32-S3 模组高 2.4 ~ 3.2 mm，需要确认外壳两面的限高。
- 电池：**2000 mAh**（已确认）。充电芯片用 **SY6970**（已确认），电池电压由它经 I²C 读取。
  芯片上电默认充电电流 2.048 A（约 1C），固件启动后设成 1 A（0.5C）；电芯规格书允许的最大充电电流还要确认。
  是否需要电量计待定。
