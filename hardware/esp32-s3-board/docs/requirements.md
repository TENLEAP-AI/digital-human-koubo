## IO 预算

### 可用引脚

按 ESP32-S3-WROOM-1U-N16R8（16 MB Flash、8 MB PSRAM、IPEX 天线座）计算。
模组引出 36 个 GPIO，其中 GPIO35 / 36 / 37 被 8 MB PSRAM 占用，**可用 33 个**：GPIO0 ~ 21、GPIO38 ~ 48。

### 放到 IO 扩展芯片上的慢信号（不占原生 GPIO）

用一颗 16 位 I²C 扩展芯片（XL9555 / TCA9555 一类），正好 16 路：

| 信号 | 路数 |
|---|---|
| 按键 KEY1 ~ KEY6 | 6 |
| Air780E：开机 PWRKEY、关机 RESET、状态 STATUS、DTR、电源使能 | 5 |
| 屏复位、触摸复位 | 2 |
| 前摄待机、后摄待机（切换前后摄） | 2 |
| 功放使能 | 1 |

不接或不占引脚的：摄像头复位（接上电复位电路，软件复位走 I²C）、触摸中断（改为轮询）、
Air780E 的 RI（不接）、充电状态（走充电芯片的 I²C 或指示灯）、SIM 卡检测（接 Air780E）、复位键（直接接 ESP32 的 EN）。

### 方案一：SPI 屏 —— 够用，含 TF 卡后全部用完

| 功能 | 原生 GPIO | 明细 |
|---|---|---|
| 摄像头（8 位并口，前后摄共用） | 12 | D0 ~ D7、PCLK、VSYNC、HREF、XCLK |
| 屏（四线 SPI） | 4 | CLK、MOSI、CS、DC |
| 背光调光 | 1 | PWM |
| 音频 | 4 | BCLK、WS、麦克风数据、功放数据（麦克风和功放共用时钟） |
| Air780E | 4 | TX、RX、RTS、CTS |
| I²C 总线 | 2 | 触摸、摄像头配置、扩展芯片、充电芯片共用 |
| USB | 2 | 下载、调试 |
| 扩展芯片中断 | 1 | 按键响应；休眠时按键唤醒 |
| 电池电压检测 | 1 | ADC |
| **小计（不含 TF 卡）** | **31** | 剩 2 个 |
| TF 卡（与屏共用 SPI 总线） | 2 | MISO、片选 |
| **合计（含 TF 卡）** | **33** | **剩 0 个** |

引脚分配草案（方案一，含 TF 卡）：

| GPIO | 用途 | 选这个脚的原因 / 注意 |
|---|---|---|
| 0 | 屏 DC | 启动配置脚：复位时必须为高。接的是屏的输入脚，不会被拉低。另留 BOOT 测试点 |
| 1 | 扩展芯片中断 | 属于休眠时仍可用的引脚，能用来唤醒 |
| 2 | 功放数据 | |
| 3 | 麦克风数据 | 启动配置脚，默认不起作用 |
| 4 ~ 8 | 摄像头 D0 ~ D4 | |
| 9 | 电池电压检测 | ADC1（Wi-Fi 工作时也能用的那组 ADC） |
| 10 / 11 / 12 | 屏 CS / MOSI / CLK | ESP32-S3 的专用高速 SPI 引脚 |
| 13 / 14 | TF 卡 MISO / 片选 | 与屏共用 MOSI、CLK |
| 15 / 16 | Air780E RTS / CTS | 串口 0 的专用流控引脚 |
| 17 / 18 / 21 | 摄像头 D5 ~ D7 | |
| 19 / 20 | USB D- / D+ | |
| 38 / 39 / 40 / 41 | 摄像头 PCLK / XCLK / VSYNC / HREF | |
| 42 / 46 | 音频 BCLK / WS | GPIO46 是启动配置脚，复位时要为低；接的都是输入脚，没问题 |
| 43 / 44 | Air780E 串口发 / 收 | 串口 0 的专用引脚，跑 921600 最稳 |
| 45 | 背光调光 | 启动配置脚，复位时必须为低；默认下拉，正好是"上电背光关" |
| 47 / 48 | I²C SDA / SCL | |

这个分配的代价：

- **没有任何备用引脚**。之后想加指示灯、4G 来数据唤醒主控、触摸中断等，都没有脚可用。
- **串口 0 给了 Air780E**，板上不再有独立的调试串口，调试和下载全靠 USB。
  ESP32-S3 上电时会从串口 0 打印启动信息，Air780E 会收到一小段乱码（它此时还没开机，无影响）。
- 四个启动配置脚（GPIO0、3、45、46）全部用上了，外接的器件在复位瞬间不能把它们拉到错误电平。
- 麦克风和功放共用时钟，两者必须用同一个采样率。

想留出余量，可以选下面的做法（每条省的引脚数写在后面）：

| 做法 | 省几个 | 代价 |
|---|---|---|
| 主板不带 TF 卡 | 2 | 没有本地存储扩展 |
| 用带 I²C 电压检测的充电芯片（BQ25895 一类）读电池电压 | 1 | 充电芯片选型受限 |
| 摄像头时钟用板上晶振，不由 ESP32 提供 | 1 | 多一颗晶振，待机功耗略增 |
| 屏的片选直接接地 | 1 | TF 卡不能再和屏共用总线 |
| Air780E 不接 RTS / CTS | 2 | 高波特率下可能丢数据，网速要降 |
| 改用 2 MB PSRAM 的模组（N16R2） | 多出 3 个 | 内存只有 2 MB，摄像头 + 界面 + 语音同时跑会很紧 |

### 方案二：实际选定的屏 LB28BOE47（480 × 640）—— 能接，但要砍功能，零余量

屏厂确认图给出的信息：2.83 寸 IPS，480 × 640，驱动芯片 **NV3049F**（不是 ST7701），接口"SPI + RGB"，22 脚 FPC。

| 脚 | 信号 | 脚 | 信号 | 脚 | 信号 |
|---|---|---|---|---|---|
| 1 | LEDA（背光 +） | 9 | G5 | 17 | HSYNC |
| 2 | LEDK（背光 −） | 10 | G4 | 18 | DE |
| 3 | SDA | 11 | G3 | 19 | VSYNC |
| 4 | SCL | 12 | G2 | 20 | RST |
| 5 | NC | 13 | G1 | 21 | GND |
| 6 | VCI（电源） | 14 | G0 | 22 | GND |
| 7 | G7 | 15 | CS | | |
| 8 | G6 | 16 | DOTCLK | | |

我对这份引脚表的解读（**标 ★ 的需要屏厂确认**）：

- ★ 数据线只有 8 根（G0 ~ G7），应该是 **8 位串行 RGB**：每个像素分 3 个时钟送出。
  乐鑫 LCD 指南写明 ESP32-S3 的 RGB 接口支持 16 位 RGB565 和 8 位 RGB888 两种，所以这种屏 ESP32-S3 能驱动。
- SDA、SCL、CS 是三线 SPI，只用来发初始化命令，可以挂在 IO 扩展芯片上，不占原生 GPIO。RST 也挂扩展芯片。
- 屏没有显存，主控要不停地送数据。帧缓冲 480 × 640 × 3 = 921 600 字节，放在 PSRAM 里，所以必须用 8 MB PSRAM 的模组。
- 每秒刷 30 帧需要约 32 MHz 的像素时钟（按每行每帧各加约 40 个消隐周期估算）。
  这个数据量 ESP32-S3 带得动，但同时还要跑摄像头，内存总线负担重，**有画面抖动的风险，要打样后才能确认**。
- 这条排线上没有触摸信号，触摸屏应该另有一条排线。
- 背光是 LEDA / LEDK 两根线，需要恒流驱动，电压电流待查。

引脚预算（TF 卡是必须的）：

这块屏不走 SPI 总线，TF 卡没法像方案一那样和屏共用总线，只能单独接（SD 一线模式：CLK、CMD、D0，3 个引脚）。

| | 引脚数 |
|---|---|
| 屏、背光、TF 卡以外的部分 | 26 |
| 屏：8 数据 + DOTCLK + HSYNC + VSYNC + DE | 12 |
| 背光调光 | 1 |
| TF 卡 | 3 |
| 合计 | 42 |
| 可用 | 33 |
| **缺口** | **9** |

把能省的全部省掉：

| 做法 | 省几个 | 代价 |
|---|---|---|
| ★ 屏只用 DE 模式（不接行场同步） | 2 | 要看 NV3049F 是否支持，需要屏厂确认 |
| 电池电压由带 I²C 检测的充电芯片读 | 1 | 充电芯片选型受限 |
| 摄像头时钟用板上晶振 | 1 | 多一颗晶振 |
| Air780E 不接 RTS / CTS | 2 | 高波特率下可能丢数据，网速要降 |
| 背光不由 ESP32 直接调光 | 1 | 扩展芯片要从 16 路换成 24 路 |
| 扩展芯片不接中断，改为轮询 | 1 | 按键不能把主控从休眠中唤醒 |
| **合计** | **8** | |

42 − 8 = 34，仍然比 33 多 1 个。

**结论：TF 卡必须有的前提下，ESP32-S3 接不下这块屏。** 只有不带 TF 卡时才勉强放得下（见上一版分析：
同时放弃流控和直接调光后刚好 33 个，零余量）。

之前按 ST7701（16 根数据线）估算的"缺 14 个、做不了"不适用于这块屏。

可选的出路：

1. **换成带显存的 SPI 屏**（比如 2.8 寸 240 × 320 的 ST7789）：回到方案一，TF 卡和屏共用总线，33 个引脚刚好用完；
   再用"充电芯片读电池电压"和"摄像头用板上晶振"两招，可以留出 2 个备用引脚。显示不占内存总线。
2. **保留这块 480 × 640 的屏，放弃 TF 卡**：勉强放得下，但没有流控、没有备用引脚，流畅度要打样验证。
3. **屏和 TF 卡都要**：换主控（例如带 MIPI 的 ESP32-P4，另配一颗 Wi-Fi 芯片），整个方案重排。

## 其它待定

- 前后摄像头共用一组并口数据线时，要确认两颗传感器待机时数据脚是否为高阻；不是的话要加总线开关。
  前摄的具体型号还没定。
- 屏：NV3049F 的数据手册或屏厂的初始化代码、RGB 模式（8 位串行？DE 还是行场同步）、背光电压电流、FPC 间距。
- 触摸屏：芯片型号和排线引脚定义。
- 6 个按键是否包含开关机键；开关机用"长按进出休眠"还是"硬件断电"。
- 外形：是否要与参考主板的外形、螺丝孔和座子位置一致。参考主板两面元件最高 1.75 ~ 1.9 mm，
  而 Air780E 高 2.3 mm、ESP32-S3 模组高 2.4 ~ 3.2 mm，需要确认外壳两面的限高。
- 电池容量和充电电流；是否需要电量计。
