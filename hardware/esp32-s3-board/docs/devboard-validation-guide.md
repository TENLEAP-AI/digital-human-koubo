# 开发板验证教程

画板之前，用现成的开发板把方案里没有把握的地方先测出来。全程飞线，不需要打板。

**2026-11-12 更新：** 现在有两家屏在打样（见 [两家屏的打样汇总](display-samples-two-makers.md)）。
NV3049F 的 8 位串行 RGB 样品按第三 ~ 五节测，排线脚位和第三节的接线表一致；ST7102 的 QSPI 样品按第八节测。
两家测同样的几件事，记下数字对比。文中的 LB28BOE47 是最早选的一块现成的 NV3049F 串行 RGB 屏，
样品没到之前，可以先买一两片它，把串行 RGB 的帧率和闪烁提前测出来。

要回答的问题只有四个：

| 编号 | 问题 | 为什么重要 |
|---|---|---|
| A | 这块屏（LB28BOE47）在 ESP32-S3 上能稳定刷到多少帧？低刷新率下闪不闪？ | 决定方案能不能成立 |
| A | 8 根数据线里哪几根有效？只接 5 根颜色能不能接受？只用 DE 行不行？ | 决定 PCB 上屏怎么接、能不能省出引脚 |
| B | 屏在刷新的同时开摄像头，画面会不会漂移？取景有几帧？ | 决定产品体验 |
| C | 再加上 USB 4G 上传照片，屏还稳不稳？ | 决定整机能不能同时工作 |

TF 卡和音频风险低，放到第一版验证板上再测。

## 一、要准备的东西

| 物料 | 说明 |
|---|---|
| ESP32-S3-DevKitC-1-N16R8 | 乐鑫官方开发板。**必须是 N16R8 或 N8R8**（八线 8 MB PSRAM），其它型号测不了 |
| 屏 LB28BOE47 | 2 ~ 3 片，飞线容易损坏排线 |
| FPC 转接板，22 脚 | 间距要和屏的排线一致，**先问屏厂排线间距**再买 |
| 背光供电 | 可调电源（带限流）或背光升压恒流小板。背光的电压电流要问屏厂 |
| OV2640 摄像头模块 | 买带 2.54 mm 排针的版本，方便飞线 |
| Air780E 开发板 | 合宙 Core-Air780E 或同类，烧 AT 固件；配一张已激活的 SIM 卡和 4G 天线 |
| 5 V / 2 A 电源 | 单独给 Air780E 开发板供电 |
| 杜邦线 | **越短越好，10 cm 以内**。屏和摄像头的信号有二三十兆赫兹，线长了会出假问题 |
| 逻辑分析仪或示波器 | 可选但强烈建议，用来量实际的像素时钟和帧率 |
| 手机 | 用慢动作录像看屏有没有闪烁 |

向屏厂要的东西（开始之前至少拿到前两项）：

1. LB28BOE47 的初始化代码（串行 RGB 版）。
2. 背光的电压和电流、FPC 间距。
3. 推荐时序：DOTCLK 范围、刷新率范围、行场的前后沿和同步脉宽。
4. 8 根数据线 G0 ~ G7 里哪 6 根有效，三个颜色字节的发送顺序。

**背光注意**：LEDA / LEDK 不能直接接 3.3 V 或 5 V。用可调电源时先把限流调到 10 mA，再慢慢加电压到灯亮。

## 二、软件环境

- ESP-IDF v5.3 或更新。
- 开发板上有两个 USB 口：标 **UART** 的用来烧录和看日志；标 **USB** 的在测试 C 里接 Air780E。
- 用到的官方组件和示例：

| 用途 | 来源 |
|---|---|
| RGB 屏驱动 | ESP-IDF 自带，示例 `examples/peripherals/lcd/rgb_panel` |
| 三线 SPI 发初始化命令 | 组件 `espressif/esp_lcd_panel_io_additions` |
| 摄像头 | 组件 `espressif/esp32-camera` |
| USB 4G | 组件 `espressif/iot_usbh_modem`，示例在 esp-iot-solution 的 `examples/usb/host/usb_cdc_4g_module` |

menuconfig 里先按下面设置（出自乐鑫 LCD FAQ）：

```
CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y
CONFIG_FREERTOS_HZ=1000
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_SPIRAM_SPEED_80M=y
CONFIG_SPIRAM_FETCH_INSTRUCTIONS=y
CONFIG_SPIRAM_RODATA=y
CONFIG_ESP32S3_DATA_CACHE_LINE_64B=y
CONFIG_COMPILER_OPTIMIZATION_PERF=y
```

PSRAM 先用 80 MHz。120 MHz 是实验性功能，乐鑫提示有温度稳定性风险，只作为对比测一下，不作为量产依据。

## 三、测试 A：单独点屏（最重要）

### 接线

屏的信号全部接在开发板 J1 一侧，线可以做得很短。

| 屏排线脚 | 信号 | 开发板 GPIO |
|---|---|---|
| 14 / 13 / 12 / 11 | G0 / G1 / G2 / G3 | 4 / 5 / 6 / 7 |
| 10 / 9 / 8 / 7 | G4 / G5 / G6 / G7 | 15 / 16 / 17 / 18 |
| 16 | DOTCLK | 8 |
| 17 | HSYNC | 9 |
| 18 | DE | 10 |
| 19 | VSYNC | 11 |
| 15 | CS | 12 |
| 4 | SCL | 13 |
| 3 | SDA | 14 |
| 20 | RST | 3 |
| 6 | VCI | 3V3 |
| 21、22 | GND | GND |
| 1、2 | LEDA、LEDK | 背光电源 |
| 5 | NC | 不接 |

### 第 1 步：发初始化命令

用 `esp_lcd_panel_io_additions` 创建三线 SPI 接口（下面的写法出自乐鑫《RGB LCD 详解》）：

```c
esp_lcd_panel_io_3wire_spi_config_t io_config = {
    .line_config = {
        .cs_io_type = IO_TYPE_GPIO,  .cs_gpio_num = 12,
        .scl_io_type = IO_TYPE_GPIO, .scl_gpio_num = 13,
        .sda_io_type = IO_TYPE_GPIO, .sda_gpio_num = 14,
        .io_expander = NULL,
    },
    .expect_clk_speed = PANEL_IO_3WIRE_SPI_CLK_MAX,
    .spi_mode = 0,
    .lcd_cmd_bytes = 1,
    .lcd_param_bytes = 1,
    .flags = { .use_dc_bit = 1, .del_keep_cs_inactive = 1 },
};
esp_lcd_panel_io_handle_t io = NULL;
ESP_ERROR_CHECK(esp_lcd_new_panel_io_3wire_spi(&io_config, &io));
```

然后按屏厂给的初始化代码，一条一条用 `esp_lcd_panel_io_tx_param(io, 命令, &参数, 1)` 发出去。要点：

- 先硬件复位：RST 拉低 50 ms 以上再拉高，等 120 ms。
- 屏厂代码里的延时照搬。通常"退出休眠 0x11"和"开显示 0x29"之后各要等 200 ms 左右。
- 公开的 NV3049F 驱动（见 `nv3049f-research.md`）用的是"时钟空闲为低、上升沿采样"，对应 `spi_mode = 0`。不亮时可以试 `spi_mode = 3`。

屏厂代码还没到手时，可以对照 `nv3049f-research.md` 里列的两份公开驱动了解命令格式，但其中的伽马和栅极参数是别的玻璃的，不要指望直接点亮。

### 第 2 步：配置 RGB 接口

在官方 `rgb_panel` 示例的基础上改这几处：

```c
esp_lcd_rgb_panel_config_t panel_config = {
    .data_width = 8,            // 8 根数据线
    .bits_per_pixel = 24,       // 串行 RGB：每个像素 3 个字节
    .clk_src = LCD_CLK_SRC_DEFAULT,
    .num_fbs = 1,
    .bounce_buffer_size_px = 10 * 480,
    .disp_gpio_num = -1,
    .pclk_gpio_num = 8,
    .hsync_gpio_num = 9,
    .de_gpio_num = 10,
    .vsync_gpio_num = 11,
    .data_gpio_nums = { 4, 5, 6, 7, 15, 16, 17, 18 },   // G0 ~ G7
    .timings = {
        .pclk_hz = 16 * 1000 * 1000,   // 从 16 MHz 开始
        .h_res = 480,
        .v_res = 640,
        // 下面六个数按屏厂给的时序填
        .hsync_pulse_width = 0, .hsync_back_porch = 0, .hsync_front_porch = 0,
        .vsync_pulse_width = 0, .vsync_back_porch = 0, .vsync_front_porch = 0,
    },
    .flags.fb_in_psram = true,
};
```

说明：

- 上面的字段名来自 ESP-IDF 的 RGB LCD 文档。时钟极性等标志位按屏厂时序图设置。
- 屏厂没给时序时，可以先参考公开资料里同一颗芯片的数：场同步 4、场后沿 14、场前沿 16（联发科那份 2.8 寸 480 × 640 驱动）。
- **行方向的前后沿，在串行模式下单位是"像素"还是"时钟周期"，我没有从文档里确认。** 用逻辑分析仪量一下 HSYNC 的周期就能定：
  周期应该等于（480 × 3 + 行消隐）个 DOTCLK。

### 第 3 步：画测试图

不用 LVGL，直接往帧缓冲里写。依次显示：

| 测试图 | 看什么 |
|---|---|
| 全屏纯红、纯绿、纯蓝、白、黑 | 颜色对不对。如果红显示成绿，说明三个字节的顺序不是红绿蓝，调整写入顺序 |
| 8 条竖条，每条只点亮一个数据位（0x01、0x02 … 0x80），红绿蓝各做一遍 | **哪几根数据线有效。** 看不出亮度变化的那几位就是面板不用的位 |
| 0 ~ 255 的灰度渐变 | 有没有色阶断层 |
| 单像素宽的黑白竖线、棋盘格 | 画面有没有抖动、错位 |
| 一条匀速移动的竖条 | 有没有撕裂 |

### 第 4 步：扫像素时钟

每个档位至少跑 10 分钟，填表。帧率可以注册 `on_vsync` 回调数每秒的次数，或者用逻辑分析仪量 VSYNC。

| DOTCLK | 实测帧率 | 画面稳定？ | 有无横向漂移 | 慢动作下有无闪烁 |
|---|---|---|---|---|
| 12 MHz | | | | |
| 16 MHz | | | | |
| 20 MHz | | | | |
| 24 MHz | | | | |
| 28 MHz | | | | |
| 32 MHz | | | | |
| 36 MHz | | | | |
| 40 MHz | | | | |

按当前掌握的消隐参数估算，20 MHz 约 20 帧 / 秒，29 MHz 约 30 帧 / 秒。

然后在"最高的稳定档位"和"刚好不闪的最低档位"上各重复三种情况：

1. 关掉 Bounce Buffer（把 `bounce_buffer_size_px` 设为 0）对比。
2. 打开 Wi-Fi 并持续收发数据（比如循环下载一个文件）。
3. 连续写 Flash（比如循环写 NVS）。

漂移通常就出现在第 2、3 种情况下。

### 第 5 步：试能不能省引脚

| 试验 | 做法 | 结论填这里 |
|---|---|---|
| 只接 5 根数据线 | 把无效位和最低几位从 GPIO 上拔掉、接到 GND，代码里对应的 `data_gpio_nums` 填 −1 | 颜色能否接受： |
| 只接 6 根数据线 | 同上，保留 6 根有效位 | 和 8 根有无差别： |
| 只用 DE | `hsync_gpio_num`、`vsync_gpio_num` 填 −1，线拔掉 | 能否稳定显示： |
| 只用行场同步 | `de_gpio_num` 填 −1，线拔掉 | 能否稳定显示： |

后两项可能还要改初始化命令里的模式寄存器，问屏厂。

### 测试 A 通过的标准

- 在某个 DOTCLK 下，开着 Wi-Fi 连续跑 30 分钟，画面不漂移、不花屏。
- 这个档位的刷新率不低于屏厂给的最小值，慢动作下看不出明显闪烁。

**如果在屏不闪的最低刷新率下 ESP32-S3 已经出现漂移，这块屏就不适合 ESP32-S3，后面的测试不用做了。**

## 四、测试 B：屏 + 摄像头同时工作

### 接线

屏只留 5 根数据线（接测试 A 里确认有效的最高 5 位，其余接 GND）。屏的 RST 改接到开发板的 RST 脚，让屏跟着开发板一起复位，腾出 GPIO3。

| 屏信号 | GPIO | | 摄像头信号 | GPIO |
|---|---|---|---|---|
| 5 根数据线 | 4 / 5 / 6 / 7 / 15 | | D0 / D1 / D2 / D3 | 16 / 17 / 18 / 3 |
| DOTCLK | 8 | | D4 / D5 / D6 / D7 | 42 / 41 / 40 / 39 |
| HSYNC | 9 | | PCLK | 47 |
| DE | 10 | | VSYNC | 21 |
| VSYNC | 11 | | HREF | 48 |
| CS / SCL / SDA | 12 / 13 / 14 | | XCLK | 38 |
| RST | 开发板 RST 脚 | | SDA / SCL | 1 / 2 |

摄像头模块的 PWDN 接 GND，RESET 接 3V3。开发板上的彩灯接在 GPIO38 或 GPIO48 上（看板子版本），测试时可能乱闪，不影响结果。

摄像头配置的字段名来自 esp32-camera 的 README，按上表填 `pin_d0` ~ `pin_d7`、`pin_pclk`、`pin_vsync`、`pin_href`、`pin_xclk`、`pin_sccb_sda`、`pin_sccb_scl`，`xclk_freq_hz` 用 20000000。

### 步骤

1. **取景**：摄像头设为 QVGA（320 × 240）、RGB565，循环取帧，把每帧放大后写进屏的帧缓冲。记录取景帧率，观察屏有没有漂移。
2. **拍照**：切到 UXGA（1600 × 1200）、JPEG，拍一张，记录从按下到拿到数据的时间和 JPEG 大小。拍照过程中屏要保持显示。
3. 连续"取景 30 秒 → 拍一张"循环 30 分钟。

乐鑫技术参考手册给的限制是：屏和摄像头同时工作时，两者的总数据量要低于 80 MB / 秒。

| 记录项 | 结果 |
|---|---|
| 取景帧率 | |
| 取景时屏是否稳定 | |
| 拍 200 万 JPEG 的耗时 | |
| 拍照瞬间屏有无花屏、黑屏 | |
| 30 分钟循环有无异常 | |

### 通过标准

取景和拍照全程屏不漂移、不花屏；取景帧率达到你能接受的水平（低于 8 帧 / 秒手感会明显卡）。

## 五、测试 C：再加上 USB 4G

### 接线

| Air780E 开发板 | 接到 |
|---|---|
| USB D− | 开发板 GPIO19 |
| USB D+ | 开发板 GPIO20 |
| GND | 开发板 GND |
| 电源 | 单独的 5 V / 2 A 电源，不要从 ESP32 开发板取电 |

最省事的做法是剪一根 USB 线，把里面的 D+、D−、GND 三根线接到开发板排针上，VBUS 那根不接。

### 步骤

1. 先单独跑乐鑫的 `usb_cdc_4g_module` 示例，确认能识别 Air780E、拨号成功、能 ping 通外网。

2. 把 4G 部分合进测试 B 的程序：拍一张 200 万 JPEG，通过 4G 用 HTTP 上传到任意服务器。
3. 上传的同时保持屏显示和取景，观察屏。
4. 循环 30 分钟，其间故意让 4G 断线重连几次（拔天线或进屏蔽环境）。

## 六、测完之后

把三张记录表和下面几个结论发给我，我据此定 PCB：

1. 屏稳定工作的 DOTCLK 和刷新率。
2. 有效的数据线是哪几根，最终接 5 根还是 6 根。
3. DE 模式下 HSYNC、VSYNC 能不能省。
4. 取景帧率和拍照耗时。
5. 加上 4G 后有没有新问题。

| 测试结果 | 下一步 |
|---|---|
| A、B、C 都通过 | 按方案三画第一版验证板 |
| A 通过，B 或 C 有漂移 | 调软件（Bounce Buffer 大小、任务分核、降低取景分辨率），仍不行再评估 |
| A 不通过 | 这块屏不适合 ESP32-S3，需要换屏 |

## 七、常见问题

| 现象 | 先查什么 |
|---|---|
| 背光亮但全白或全黑 | 初始化命令没发进去：查 CS、SCL、SDA 接线和 `spi_mode`；查 RST 时序 |
| 有图像但颜色错 | 三个颜色字节的顺序；数据线接反了高低位 |
| 图像整体偏移或卷动 | 前后沿参数不对；行方向的单位弄错（像素和时钟周期差 3 倍） |
| 画面间歇性横向漂移 | DOTCLK 太高；没开 Bounce Buffer；没开"代码放进 PSRAM 运行"那两项配置 |
| 高 DOTCLK 下出现噪点、花线 | 先怀疑飞线太长，换短线或降低 GPIO 驱动强度后再判断是不是芯片的上限 |
| 开机日志提示 PSRAM 初始化失败 | 开发板不是 R8 型号，或 menuconfig 里没选八线模式 |

## 八、QSPI 屏（ST7102 样品）

和串行 RGB 屏的区别：只有 6 根信号线加 TE；没有像素时钟和行场同步，主控按命令把一块块图像写进去。
屏有没有显存，决定测法（见第 3 步）。**开测前要拿到屏厂的书面答复**：QSPI 的指令格式、初始化代码、SCK 最高频率、有没有显存。

### 接线

用主板打算给屏的同一组引脚（GPIO38 ~ 42、47、48），这样测出来的速度就是主板上的速度。
ESP32-S3-DevKitC-1 v1.1 板上的彩灯接在 GPIO38，所以把 TE 放在 GPIO38（TE 是屏输出给主控，彩灯跟着闪一下不影响）。

| 屏排线脚 | 信号 | 开发板 GPIO |
|---|---|---|
| 5 | CS | 39 |
| 6 | SCK | 40 |
| 8 | D0 | 41 |
| 9 | D1 | 42 |
| 11 | D2 | 47 |
| 12 | D3 | 48 |
| 14 | TE | 38 |
| 16 | RESET | 3 |
| 3、20、22 | VCC | 3V3 |
| 4、7、10、13、15、17、18 | GND | GND |
| 1、2 | LEDA、LEDK | 背光电源，限流 20 mA |
| 19、21 | NC | 不接 |

时钟线 SCK 和四根数据线最要紧，飞线越短越好，每根旁边最好配一根地线。

### 第 1 步：建 QSPI 接口、发初始化命令

ESP-IDF 的 `esp_lcd` 支持 QSPI 屏：`spi_bus_initialize` 时把 D0 ~ D3 分别填进 `data0_io_num` ~ `data3_io_num`，
建接口时 `esp_lcd_panel_io_spi_config_t` 里打开 `flags.quad_mode`。命令和参数各占几位、写命令和写图像用什么指令码，
按屏厂的答复填；然后用 `esp_lcd_panel_io_tx_param` 一条条发初始化命令。乐鑫组件库里现成的 QSPI 屏驱动（比如 ST77916）
可以拿来对照写法，具体指令以屏厂给的为准。

### 第 2 步：画测试图

和第三节第 3 步一样：纯色、灰度渐变、单像素竖线和棋盘格、匀速移动的竖条。
用 `esp_lcd_panel_io_tx_color` 写一整屏。看颜色顺序（RGB565 的高低字节可能要对调）、有没有错位。

### 第 3 步：测帧率

| SCK | 写一整屏的时间 | 折合帧率 | 画面稳定？ |
|---|---|---|---|
| 20 MHz | | | |
| 40 MHz | | | |
| 60 MHz | | | |
| 80 MHz | | | |

写一整屏的时间用 `esp_timer_get_time()` 前后计时，或者用逻辑分析仪量 CS 拉低的时间。
40 MHz 下理论上约 30 ms 一屏，也就是每秒约 32 帧。

- **屏有显存**：画面不动时主控可以不送数据。再测"只刷一块区域"（比如 480 × 200 的取景框）的帧率。
- **屏没有显存**：主控必须按屏厂要求的节拍一直送。测的是"一直送 30 分钟、同时开 Wi-Fi"会不会断帧、花屏。

### 第 4 步：TE 和撕裂

打开 TE，等 TE 信号来了再开始写一屏，显示匀速移动的竖条，看有没有撕裂。用逻辑分析仪量 TE 的频率，就是屏自己的刷新率。

### 第 5 步：加摄像头、加 4G

和第四、五节一样，把摄像头取景画到屏上，再加上 4G 上传，看帧率掉多少、画面稳不稳。

### QSPI 屏通过的标准

- 整屏刷新每秒 20 帧以上（屏有显存时，取景框区域每秒 20 帧以上也可以）。
- 开着 Wi-Fi 和摄像头连续跑 30 分钟，不花屏、不断帧。
- 用 TE 同步后看不出撕裂。
