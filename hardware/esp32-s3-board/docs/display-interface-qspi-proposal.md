# 屏的 QSPI 接口定义（给屏厂评估）

日期：2026-11-12。对应主板：Zeebuddy 主板 V1。状态：**提案，等屏厂评估**；主板还没有按它改。

## 1. 为什么提这个方案

我们的主控是 ESP32-S3，没有 MIPI-DSI 接口，驱动不了 HD28142C22 现有的 MIPI 版本。屏厂提出同尺寸的屏可以改成 QSPI 接口。
QSPI 只要 6 根信号线，比现在主板上的"8 位串行 RGB + 三线 SPI"（13 根）少一半，对我们是好事。下面是我们希望的接口和脚位。

**先说明一点：QSPI 版本不可能还是 NV3049。** NV3049 的数据手册写明它只有 MIPI-DSI 和并口 RGB 两种图像接口，没有 QSPI，
也没有显存。所以 QSPI 版本用的一定是另一颗驱动芯片，玻璃的绑定也会跟着变——这是一块新的屏，不是给 HD28142C22 换一条排线。
下面的第 4 节第 1 个问题（驱动芯片的确切型号）因此是最要紧的。

**2026-11-12 补充：ST7701P 也没有 QSPI。** 查了屏厂给的 ST7701P 规格书（V1.2，2025-02）：没有显存；图像接口只有并口 RGB
（16 / 18 / 24 位）和 MIPI；另有三线、四线串行接口，但只能发命令。规格书里的"4-line Serial Interface"是普通的四线 SPI，
不是四根数据线并行的 QSPI，两者容易说混。三卷都已查过：接口选择脚 IM[3:0] 只有两类组合——"并口 RGB + SPI（8 / 9 / 16 位）"
和"MIPI（可加 SPI）"，并注明"SPI 只能写命令"；像素格式寄存器（3Ah）只有 16 / 18 / 24 位三种；像素时钟周期最短 33 ns（约 30 MHz）。
并口 RGB 最少也要 16 根数据线加 4 根同步线，主板上没有这么多空脚。所以这份提案目前**没有对应的芯片**，除非屏厂另有一颗真正支持 QSPI 送图像的驱动芯片。
现在走得通的是 8 位串行 RGB（另一家供应商的 NV3049F 版本），见 [display-request-serial-rgb.md](display-request-serial-rgb.md)。

## 2. 我们对屏的要求

| 项目 | 要求 |
|---|---|
| 尺寸、分辨率 | 2.8 英寸，480 × 640（和 HD28142C22 相同） |
| 接口 | QSPI：CS、SCK、D0 ~ D3 共 6 根线，命令和图像数据走同一组线 |
| 逻辑电平 | 3.3 V |
| 供电 | 主板只给一路 3.3 V |
| 像素格式 | RGB565（16 位）。能支持 RGB666 更好 |
| **驱动芯片自带显存（GRAM）** | **强烈希望有。** 有显存，屏自己刷新，主控只在画面变化时送数据；没有显存，主控要一帧不落地连续送，和 RGB 屏一样吃主控的内存带宽 |
| SCK 频率 | 请给出最大值。我们计划用 40 MHz |
| TE（撕裂同步）输出 | 需要 |
| 复位 | RESET 脚，低有效 |
| 背光 | 和 HD28142C22 相同：6 颗灯串联，18 V，20 mA。主板已按这个做好 |
| 触摸 | 另配，不在这条排线上 |

## 3. 脚位（22 脚，0.5 mm 间距）

排线的外形、长度、金手指朝向都沿用 HD28142C22 现有的排线，**只换信号的定义**。背光、电源、地、复位的位置和 MIPI 版本一样，
原来三对 MIPI 差分线的位置换成 QSPI 的线，改动最小：

| 脚 | MIPI 版本（现有） | **QSPI 版本（我们要的）** | 方向 | 主板这边 |
|---|---|---|---|---|
| 1 | LEDA | LEDA | 电源 | 背光升压输出，约 18 V |
| 2 | LEDK | LEDK | 电源 | 背光恒流，20 mA |
| 3 | VCC | VCC | 电源 | 3.3 V |
| 4 | GND | GND | | 地 |
| 5 | D0N | **CS** | 主板 → 屏 | ESP32 GPIO |
| 6 | D0P | **SCK** | 主板 → 屏 | ESP32 GPIO，时钟。旁边第 7 脚是地 |
| 7 | GND | GND | | 地 |
| 8 | CLKN | **D0** | 双向 | ESP32 GPIO |
| 9 | CLKP | **D1** | 双向 | ESP32 GPIO |
| 10 | GND | GND | | 地 |
| 11 | D1N | **D2** | 双向 | ESP32 GPIO |
| 12 | D1P | **D3** | 双向 | ESP32 GPIO |
| 13 | GND | GND | | 地 |
| 14 | GND | **TE** | 屏 → 主板 | ESP32 GPIO |
| 15 | GND | GND | | 地 |
| 16 | RESET | RESET | 主板 → 屏 | I/O 扩展芯片，主板有下拉，上电默认复位 |
| 17 | GND | GND | | 地 |
| 18 | GND | GND | | 地 |
| 19 | NC | NC | | 不接 |
| 20 | VCC | VCC | 电源 | 3.3 V |
| 21 | NC | NC | | 不接 |
| 22 | VCC | VCC | 电源 | 3.3 V |

和 MIPI 版本相比只有 7 个脚变了：5、6、8、9、11、12 换成 QSPI 的线，14 由地改成 TE。
如果屏厂觉得别的顺序更好出线，可以提出来，我们的主板这一部分还没有改，能配合。

排线座在主板上的位置见 [`../kicad/connector-positions.png`](../kicad/connector-positions.png)：J8，主板背面，上边缘，
从背面看第 1 脚在右。

## 4. 请屏厂答复

| # | 问题 | 屏厂答复 |
|---|---|---|
| 1 | **驱动芯片的确切型号。** ST7701S 标准的接口是"三线 SPI 发命令 + RGB 或 MIPI 送图像"，乐鑫的驱动列表里也把 ST7701 归在"SPI + RGB"一类，没有 QSPI。QSPI 版本用的是 ST7701 的哪个型号，还是同系列的 ST77903、ST77922 之类 | |
| 2 | **芯片里有没有显存（GRAM）。** 没有的话，主控必须按固定的行、帧节拍连续送数据，请给出时序要求和最低刷新率 | |
| 3 | QSPI 的协议：命令和数据各用几根线、写命令和写图像的指令码、SCK 最高多少 | |
| 4 | QSPI 模式下的完整初始化代码 | |
| 5 | 支持的像素格式（RGB565 / RGB666）；局部刷新时对起止坐标有没有限制（比如要是 4 的倍数） | |
| 6 | 有没有 TE 输出，能不能引到第 14 脚 | |
| 7 | 只给一路 3.3 V 行不行，是否还要 1.8 V | |
| 8 | 背光是否仍是 6 颗灯串联、18 V、20 mA | |
| 9 | 排线是否沿用 HD28142C22 的外形：从模组下边正中伸出、总长 40 mm、头宽 11.5 mm、金手指在模组背面那一面、从正面看第 1 脚在左 | |
| 10 | 开模费、起订量、交期；能不能先给 3 ~ 5 片样品 | |

## 5. 我们这边的顾虑，请屏厂一起看

- **数据量。** 480 × 640、16 位色，一帧约 614 KB。QSPI 40 MHz 每秒最多送约 20 MB，也就是**每秒最多约 32 帧**（整屏刷新）。
  我们要做摄像头取景和播放短片，希望整屏刷新能到每秒 20 帧以上。请屏厂确认 SCK 能不能到 40 MHz 或更高。
- **有没有先例。** 乐鑫公开的测试数据里，ESP32-S3 用 QSPI 驱动的屏最大测到 400 × 400；480 × 640 超出了这个范围。
  所以我们需要先拿样品在开发板上点亮、测帧率，确认可行之后再改主板、开排线模。

## 6. 对主板的影响（内部记录）

屏厂确认可行之后要改的地方，**现在都还没有改**：

| 项目 | 现在（8 位串行 RGB） | 改成 QSPI 之后 |
|---|---|---|
| 屏的信号线 | 数据 5 根（另 3 根接地）、DOTCLK、HSYNC、VSYNC、DE，加三线 SPI 和复位，共 13 根 | CS、SCK、D0 ~ D3、TE，加复位，共 8 根 |
| ESP32 的引脚 | GPIO38 ~ 42、47、48，另外 HSYNC / VSYNC 和串口 0（GPIO43 / 44）共用 | GPIO38 ~ 42、47 给 QSPI，GPIO48 给 TE；**串口 0 不再和屏共用** |
| I/O 扩展芯片 | LCD_RST、LCD_CS、LCD_SCL、LCD_SDA | 只剩 LCD_RST，空出 3 个脚 |
| 原理图 | R50 ~ R52、R55 ~ R57、J8 的脚位 | 都要改 |
| PCB | 屏的线从左上角的 J8 横穿到右边的 ESP32 | 线少了近一半，J8 的出线和中间那一带都会松 |
| 固件 | RGB 屏驱动，帧缓冲在 PSRAM 里由主控不停地刷 | QSPI 屏驱动；屏有显存的话主控只在画面变化时送数据 |
