# 屏打样要求：QSPI 版本（ST7102，给屏厂）

日期：2026-11-12；2026-11-13 改为 in-cell 触摸、公母座。

## 1. 一句话要求

2.8 英寸、480 × 640、驱动芯片 ST7102 的屏，图像和命令都走 **QSPI**（CS、SCK、D0 ~ D3），排线按第 3 节的 22 脚定义出；**带电容触摸**，触摸排线按第 3.1 节的 6 脚定义出。
先做 3 ~ 5 片样品，屏、in-cell 触摸和盖板做成总成一起打样。

## 2. 接口要求

| 项目 | 要求 |
|---|---|
| 尺寸、分辨率 | 2.8 英寸，480 × 640，竖屏 |
| 图像和命令接口 | **QSPI**：CS、SCK、D0 ~ D3，命令和图像都走这一组线。我们的主控没有 MIPI，引脚也不够做 RGB 并口，所以 MIPI 和并口都用不了 |
| 撕裂同步 | 需要 TE 输出，引到排线上 |
| 复位 | RESET，低有效 |
| 逻辑电平 | 3.3 V |
| 供电 | 主板只给一路 3.3 V。芯片如果还要 1.8 V 或别的电压，请在屏内部解决，或者告诉我们 |
| 像素格式 | RGB565（每个像素 16 位） |
| SCK 频率 | 我们的主控（ESP32-S31）最高 80 MHz，计划用 80 MHz，请告诉我们屏最高能到多少 |
| 背光 | **灯必须串联**，电流 20 mA，4 ~ 6 颗串联都可以（约 12 ~ 20 V）。主板的背光是升压恒流电路，**并联的灯用不了**。你们现有的 LX280BS 规格书上是 4 颗并联，这一点要改 |
| 触摸 | in-cell，屏自带；触摸信号和屏走同一条排线，见第 3.1 节 |

## 3. 屏的信号（22 个，按这个顺序排）

| 脚 | 名称 | 方向 | 说明 |
|---|---|---|---|
| 1 | LEDA | 电源 | 背光正极 |
| 2 | LEDK | 电源 | 背光负极 |
| 3 | VCC | 电源 | 3.3 V |
| 4 | GND | | 地 |
| 5 | CS | 主板 → 屏 | 片选 |
| 6 | SCK | 主板 → 屏 | 时钟 |
| 7 | GND | | 地，把时钟和数据隔开 |
| 8 | D0 | 双向 | 数据 |
| 9 | D1 | 双向 | 数据 |
| 10 | GND | | 地 |
| 11 | D2 | 双向 | 数据 |
| 12 | D3 | 双向 | 数据 |
| 13 | GND | | 地 |
| 14 | TE | 屏 → 主板 | 撕裂同步 |
| 15 | GND | | 地 |
| 16 | RESET | 主板 → 屏 | 复位，低有效 |
| 17 | GND | | 地 |
| 18 | GND | | 地 |
| 19 | NC | | 不接 |
| 20 | VCC | 电源 | 3.3 V |
| 21 | NC | | 不接 |
| 22 | VCC | 电源 | 3.3 V |

主板上的接口在主板背面的上边缘，用板对板公母座（见下面）。

**排线末端的做法：用亚奇品牌的板对板（BTB）公母座。**排线末端焊**公座**，主板上贴配套的**母座**。

- 请推荐亚奇的具体系列，给出**公座和母座的完整型号**（两者必须配套）、间距（常见 0.4 mm）、配合高度。配合高度希望 ≤1.0 mm，以结构最终确认为准。
- 上面的脚位表是**信号的顺序**。换成公母座后，请按所选型号的脚数重新排一张"母座脚号 → 信号"的对照表给我们：
  脚数比信号多的，多出的脚接地；公座和母座的脚号是镜像的，**对照表一律按主板上母座的脚号写**，避免两边对反。
- 触摸是 in-cell 的，信号本来就在屏的排线上，和屏共用这一个公母座（见第 3.1 节）。
- 排线上公座的位置、方向和背面的补强板，随排线图一起给。

## 3.1 触摸：in-cell，屏自带（2026-11-13 改）

你们说这款 2.8 寸是 in-cell 屏，触摸做在屏里面，只要贴盖板，你们可以做总成。**我们就用 in-cell，不另加触摸屏。**

in-cell 不用另贴触摸屏，但触摸的信号还是要接到主板上，主控才能读到触摸坐标。所以：

| 项目 | 要求 |
|---|---|
| 交货形式 | 总成：屏 + 盖板 + 排线，你们贴好 |
| 触摸信号 | 和屏的信号**走同一条排线、同一个公母座** |
| 接口 | I²C，主板上有 3.3 V 上拉；中断和复位低有效 |
| 电平 | 主控是 3.3 V。触摸的 I²C、中断、复位如果只能用 1.8 V，请告诉我们，我们加电平转换 |

触摸的信号，按这个顺序排在屏的信号后面：

| 顺序 | 名称 | 方向 | 说明 |
|---|---|---|---|
| 1 | TP-INT | 屏 → 主板 | 触摸中断，低有效 |
| 2 | TP-RST | 主板 → 屏 | 触摸复位，低有效。如果触摸和屏共用 RESET，就不要这一根 |
| 3 | TP-SCL | 主板 → 屏 | I²C 时钟 |
| 4 | TP-SDA | 双向 | I²C 数据 |

**第 1、2 条最要紧。** 第 1 条不成立，这个方案就做不了。第 2 条决定我们的主控忙不忙得过来。

## 5. 我们的顾虑，请一起看

- **数据量。** 480 × 640、16 位色，一帧约 614 KB。QSPI 80 MHz 每秒最多送约 40 MB，整屏刷新最多约每秒 65 帧；40 MHz 时约 32 帧。
  我们要做摄像头取景和播放短片，希望整屏刷新能到每秒 30 帧以上，所以 SCK 最好能到 60 ~ 80 MHz。芯片如果没有显存，主控就得一直按这个速度送。
- **先例。** 我们没找到这个主控用 QSPI 驱动 480 × 640 屏的公开例子。样品到了，我们先在开发板上点亮、测帧率，
  确认可行之后再改主板、开排线模具。

## 6. 样品到了我们怎么验

1. 用你们给的初始化代码点亮，显示彩条，颜色正确。
2. SCK 80 MHz（做不到就按你们给的最高值）下长时间显示稳定，不花屏。
3. 测整屏刷新的实际帧率。
4. 用 TE 同步之后，画面移动时没有撕裂。
5. 同时开摄像头取景，画面稳定。
6. 触摸：用开发板的 I²C 读出触摸的 ID，单点、两点触摸坐标正确，四个角和边缘都能点到；屏在刷新时触摸不乱跳。
