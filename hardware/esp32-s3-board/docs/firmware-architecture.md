# AI 拍学机固件系统架构和开发计划（ESP32-S31）

日期：2026-11-14。组件和数字的出处见 [espressif-resources-for-ai-camera.md](espressif-resources-for-ai-camera.md)，引脚见 [esp32-s31-pinmap.md](esp32-s31-pinmap.md)。
标"待验证"的是乐鑫资料里没写清楚、要在开发板上测出来的。

## 1. 产品功能和对应的乐鑫组件

| 功能 | 用的组件 | S31 情况 | 备注 |
|---|---|---|---|
| 拍题讲解 | ESP-ADF v3 `ai_agent` 例程（通义千问看图：拍一张 JPEG 带图提问） | 例程带 Korvo-1 配置 | 改造起点。大模型的密钥不能写进固件，见第 4 节 |
| 语音唤醒、离线命令词 | ESP-SR：WakeNet、MultiNet（最多 300 条） | 初步支持 | 自定义唤醒词要走乐鑫流程 |
| 降噪、回声消除、打断 | ESP-SR 的 AFE | 初步支持 | 单麦克风 |
| 取景、拍照 | `esp_video` + `esp_cam_sensor`，硬件 JPEG 编码 | 支持，OV2640 在列表里 | 旧的 `esp32-camera` 不支持 S31，不用 |
| 界面 | LVGL 9 + `esp_lvgl_port` / `esp_lvgl_adapter`，PPA 做旋转缩放 | 官方实测 800 × 480 每秒 50 帧 | Brookesia 要 IDF 6.2，暂不用 |
| 屏驱动 | `esp_lcd` RGB 面板驱动（16 位）+ 屏厂的初始化代码 | 支持 | ST7102 有第三方驱动可参考；ST7701 有官方驱动 |
| 英语视频、音频 | ESP-GMF `esp_player`（MP4 / AVI 容器，MJPEG 视频，AAC / MP3 音频） | 实测 MJPEG 640 × 480 每秒 66 帧 | **片源统一转 MJPEG**，H.264 软解只有 13 帧 |
| 跟读慢放、音量音质 | ESP-Audio-Effects（变速不变调、均衡、限幅） | 1.3.0 版起支持 | |
| 4G | `iot_usbh_modem` + `usb_host_cdc_acm`（USB 拨号） | 组件列了 S31 | Air780E 兼容性待验证 |
| Wi-Fi、蓝牙 | ESP-IDF 自带 | 支持 | |
| TF 卡 | ESP-IDF SDMMC，4 线 | 支持 | |
| 端侧框题（可选） | ESP-DL + 自己训练的检测模型 | 支持 | 文字识别交给云端，S31 上没有官方 OCR 模型 |
| OTA | ESP-IDF 自带的 OTA，配自己的服务器 | 支持 | RainMaker 国内能不能用没写，先不依赖 |
| 安全 | Secure Boot V2（**RSA**）+ Flash 加密 + NVS 加密 | 支持 | ECDSA 安全启动有已知漏洞，不用 |

**许可**：ADF、ESP-SR、esp_video、GMF 是"乐鑫修改版 MIT"，只能用在乐鑫芯片上，对我们没问题。

## 2. 软件分层

```
应用层   拍题讲解 │ 语音问答 │ 英语视频 / 跟读 │ 相册 │ 设置 / 家长绑定
─────────────────────────────────────────────────────────────
服务层   语音服务（唤醒、降噪、录音、播放、打断）
         相机服务（取景、拍照、JPEG）
         界面服务（LVGL、页面、字体、图片解码）
         网络服务（Wi-Fi / 4G 自动切换、证书、重连）
         云端客户端（登录、拍题请求、流式回答、语音合成）
         媒体服务（视频、音频播放，跟读慢放）
         存储（TF 卡、配置）、OTA、电源管理（电量、休眠、唤醒）
─────────────────────────────────────────────────────────────
板级层   屏（16 位 RGB）、触摸、两个摄像头和切换、麦克风、功放、
         TF 卡、两颗扩展芯片、充电芯片、Air780E 电源和复位、按键
─────────────────────────────────────────────────────────────
ESP-IDF v6.1 + 上面列的乐鑫组件
```

板级层单独做成一个组件，开发板（Korvo-1）和我们的主板各一份，上面的服务层和应用层不用改。

## 3. ESP-IDF 版本

| 组件 | 要求 |
|---|---|
| S31 本身 | ESP-IDF v6.1 起支持（第一个支持 S31 的正式版） |
| ESP-DL | ≥ 6.0 |
| ESP-ADF v3 | ≥ 5.5.2（主分支，还在快速开发，和 v2 不兼容） |
| ESP-Brookesia | 6.2（还没发布，暂不用） |

**定 ESP-IDF v6.1**，各组件锁定版本号，升级要统一评估。ADF v3 在 v6.1 上能不能完整编译，开工第一周验证。

## 4. 云端设计

```
拍学机 ──HTTPS / WebSocket──▶ 我们自己的后台 ──▶ 大模型（通义千问看图、豆包等国内模型）
                               │                └▶ 语音识别、语音合成
                               ├─ 设备身份和家长绑定
                               ├─ 内容（英语视频、题库）下发
                               └─ OTA 固件
```

- **大模型的密钥放在后台，不写进固件**。乐鑫例程是把密钥编进固件的，只适合演示：量产后密钥一旦被读出，费用和数据都会出问题。
- 设备用一机一证（出厂预置证书或设备密钥）连我们的后台，后台再转发给大模型。
- 儿童数据（照片、语音）要按国内的未成年人个人信息规定处理：上传前告知、加密传输、限期删除。
- 选哪家大模型、费用和延迟，乐鑫页面都没写，要分别向通义、豆包、扣子等询价对比。

## 5. 内存和处理器的分配（估算，待验证）

16 MB PSRAM、512 KB 内部 SRAM、双核 320 MHz。

| 用途 | PSRAM 估算 | 说明 |
|---|---|---|
| 屏的帧缓冲 | 约 1.2 MB | 480 × 640 × 2 字节 × 2 帧 |
| 摄像头帧 | 约 1.8 MB | 640 × 480 YUV422 × 3 帧 |
| JPEG 编解码缓冲 | 约 0.5 MB | |
| 语音前端和唤醒 | 约 1.1 MB | S3 上的数字，S31 待测 |
| LVGL 图片和字体缓存 | 约 1 ~ 2 MB | 中文字库按需裁剪 |
| 视频播放 | 约 1 ~ 2 MB | MJPEG 比 H.264（约 2.5 MB）省 |
| 网络、TLS、录音缓冲 | 约 1 MB | |
| **合计** | **约 7 ~ 9 MB** | 16 MB 够，留出余量 |

处理器初步分工：一个核跑网络和语音前端（S3 上语音前端约占 22%），另一个核跑界面、相机和视频。

**同时运行的规则**：放视频时关摄像头；大模型语音回答时打开回声消除，允许小朋友打断；取景时降低界面刷新。

## 6. 开发顺序（先在 Korvo-1 开发板上做）

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| 0 | 搭环境：ESP-IDF v6.1 + ADF v3，Korvo-1 上跑通乐鑫的通义看图例程 | 按键拍照、大模型语音回答 |
| 1 | 拍题讲解 MVP：接我们自己的后台（密钥不进固件），Wi-Fi 上网 | 拍一道题，3 ~ 5 秒内开始讲解 |
| 2 | 语音：唤醒词、降噪、回声消除、打断、离线命令（"拍照""下一题"） | 边放边说能打断 |
| 3 | 界面：LVGL 页面、取景框、拍照确认；屏样品到了换成我们的 480 × 640 屏 | 取景流畅，触摸正常 |
| 4 | 4G：Air780E 开发板接 USB，Wi-Fi 和 4G 自动切换 | 拔掉 Wi-Fi 能自动走 4G |
| 5 | 媒体：TF 卡、MJPEG 视频、音频、跟读慢放 | 480 × 640 视频流畅 |
| 6 | OTA、安全启动、Flash 加密、工厂测试固件 | 能远程升级，加密后能正常量产烧录 |
| 7 | 主板回来后移植板级层 | 主板上全部功能跑通 |

阶段 0 ~ 2 不依赖屏和主板，可以马上开始。

## 7. 要先验证的风险

1. ESP-SR 在 S31 上只是"初步支持"：唤醒、降噪的效果和资源占用。
2. ADF v3 在 ESP-IDF v6.1 上的稳定性。
3. 大模型例程能不能走 4G（USB 拨号）而不只是 Wi-Fi。
4. Air780E 和 `iot_usbh_modem` 的兼容性。
5. 屏、摄像头、语音、网络同时跑的性能。
6. 两颗摄像头共用一组并口时，`esp_video` 怎么切换。
7. TF 卡读 MJPEG 的速度。
8. 拍题照片的分辨率：乐鑫例程默认 640 × 480，拍作业字可能不够清楚，要试 OV2640 的 1600 × 1200 拍照加硬件 JPEG。
